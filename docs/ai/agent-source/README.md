先区分模型、执行框架和调用接口，再沿输入、状态、工具与结束条件阅读代码。每篇文章固定源码提交，给出文件位置、关键调用链和自测问题。

## 阅读路径

| 专题                                      | 公开代码范围           | 重点问题                                                     |
| ----------------------------------------- | ---------------------- | ------------------------------------------------------------ |
| [DeepSeek Harness](./deepseek-harness.md) | 官方 Agent 执行框架    | 插件如何组合能力？输入何时生效？工具如何调度与取消？         |
| [Jev 决策接口与 SDK](./jev-sdk.md)        | 官方 Python 客户端 SDK | 问题如何类型化？响应怎样校验？宿主程序怎样依据结果推进任务？ |

DeepSeek Harness 分析覆盖任务执行框架；Jev 分析覆盖公开的接口与客户端实现，不推断其未公开的模型内部算法。

## 先补齐三个概念

1. [Agent 基础](../agent/agent-basis.md)：模型提出动作，程序负责执行、记录结果并决定是否继续。
2. [结构化输出与工具调用](../llm-basis/structured-output-function-calling.md)：格式有效、语义正确和执行获准是三个不同条件。
3. [Harness Engineering](../agent/harness-engineering.md)：上下文、工具、状态、权限和生命周期共同决定系统行为。

## 用五个问题检验阅读结果

- 用户输入进入哪个队列，何时对模型生效？
- 状态的事实来源是什么，能否从记录中恢复？
- 并发操作的执行顺序与提交顺序是否相同？
- 超时、错误和取消分别由谁处理？
- 哪些结论来自源码，哪些只是需要进一步实验的推论？
