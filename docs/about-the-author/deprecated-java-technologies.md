选择学习内容时，先区分“建立基础知识”“进入一个现有项目”和“为新系统选型”三种任务。技术的年龄不能单独决定学习价值，系统现状、约束与验证成本同样重要。

## 按任务确定深度

| 当前任务 | 先掌握什么 | 需要形成的证据 |
| --- | --- | --- |
| 建立 Java Web 基础 | HTTP 请求、Servlet 生命周期、线程与资源管理 | 能解释一次请求的完整处理过程 |
| 维护现有系统 | 实际框架版本、依赖关系、构建和部署流程 | 能在隔离环境复现问题并验证修复 |
| 迁移旧模块 | 数据格式、接口契约、事务边界、回滚条件 | 新旧行为对照与回归记录 |
| 为新系统选型 | 业务需求、团队经验、维护状态与运行约束 | 有来源的对比与最小验证 |

## 阅读旧技术资料时检查什么

先确认文章与项目使用的具体版本，再区分概念说明和该版本的实现细节。对停止维护的依赖，单独核查安全更新、兼容性与替代路径。示例能编译不等于在目标环境中安全可用。

## 维护与迁移的顺序

先补观测与回归证据，再逐步替换边界明确的模块。记录请求和响应、数据约束、异常处理与事务语义，避免只对比接口名称。迁移计划要包含失败后的回退条件，并验证新旧数据能够被正确读取。
